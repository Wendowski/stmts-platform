# STMTS product and interface specification
Version 1.0 · Status: proposed build baseline · 8 November 2026
Normative words MUST, SHOULD and MAY have their ordinary requirement meanings. These are proposed product decisions, not existing service capabilities. Use this document to build one vertical slice at a time. Do not infer functioning backend services from the HTML studies.

## 1. Goal and scope
P-001 MUST support a single post entity from a short update to a long-form Markdown document, including optional photos and video. All clients MUST preserve the author's source and render equivalent structure.
P-002 MUST implement Angular web, SwiftUI iOS/iPadOS, and Kotlin Jetpack Compose Android as separate clients against a versioned API. Python backend is the preferred integration context; this handoff defines client contracts rather than a complete backend architecture.
P-003 MVP includes account/session states, Following and Discover, compose/drafts, reader/replies, reactions, reposts without commentary, bookmarks, profiles, search, settings, reporting, blocking and muting. DMs, live video, polls, subscriptions, federation, quote reposts, collaborative editing, monetization and recommendations trained on behavior are out of scope.
P-004 Public post and profile URLs MUST open for signed-out readers. Restricted drafts never appear in public URLs or indexing. MVP audience is Public only; a visible Public indicator prevents ambiguity. Private/follower-only audiences require a later privacy model.

## 2. Information architecture
| Route | View | Primary action |

| /home | Following feed | Write a statement |
| /discover | Discover feed and topics | Follow a person |
| /search?q=…&type=posts | Search posts/people/tags | Open a result |
| /compose and /drafts/:id | Create/edit draft | Publish |

NAV-001 Compact primary navigation: Home, Discover, Notifications, Profile; Write is a labeled action in the header, not a fifth ambiguous icon. Saved, Drafts and Settings are reachable from the profile menu. Medium uses a rail; expanded uses labels and shows Saved/Drafts. Search is reachable from Discover and desktop navigation.
NAV-002 Native deep links MUST resolve the canonical post ID and fetch current permissions; slugs are presentation only. Browser/native back MUST restore feed anchor, loaded items and focus when possible. A deleted/missing target returns a useful unavailable state.
NAV-003 Signed-out reactions/follow/write MUST open sign-in, retain the return route, and require an explicit retry of publication after sign-in. Never auto-publish a retained draft.

## 3. Feed and reading
FEED-001 Following sorts newest first using a stable (createdAt,id) cursor. Discover MVP is editorial/chronological by selected topic, labeled Discover. Pagination uses opaque cursors, deduplication by post ID, bounded caches and a Load more fallback; never insert new posts above the viewport without a “New statements” action.
FEED-002 A short post is ≤500 Unicode code points with no title and no block structures beyond paragraphs. It renders in full. All other posts use a title if supplied, otherwise a first-line excerpt; excerpt max 280 Unicode code points and roughly three visual lines, with explicit Continue reading. The semantic excerpt MUST be available regardless of CSS clamping. Reading time = ceil(plainTextWordCount / 220), min 1 minute, excludes source code; approximate localized metadata.
FEED-003 An article has separate title/read links and action buttons. Nested anchors are forbidden. Post menu offers copy link, mute author, block author, report; owner menu additionally offers edit/delete. Reposts show the reposter and original author, link to the original, and honor original deletion/block state.
READ-001 Reader MUST render title (optional), author, publish date, updated marker if edited, optional summary and cover, body, media, actions and threaded replies. Visible timestamps use locale; accessible/full date is available. Body measures no more than 68ch at normal text size and wraps at enlarged text size.
READ-002 Public post edits MUST retain ID and publishedAt, increment revision, update updatedAt, and show Edited. Existing bookmarks/replies remain attached. Delete requires confirmation, removes body/media access, and leaves a neutral tombstone in reply context. Server enforces ownership.
READ-003 Replies use the same safe Markdown subset, max 5,000 Unicode code points, up to 4 images OR 1 video, no document title. Render two nesting levels visually; deeper threads open a focused conversation view rather than accumulating indentation.
SOC-001 Like, bookmark, follow, and repost MUST be idempotent desired-state mutations. Optimistic updates MUST rollback on failure with a retry and polite announcement. Counts MUST reconcile to server response. Rapid taps cannot reorder stale responses; serialize or version requests. Repost toggle cannot create duplicates.
SOC-002 Block MUST hide both parties' posts/replies/notifications for the blocker and prevent interaction server-side. Mute only changes the muter's feeds/notifications. Report requires a reason, optional details, submitting/error/success states and duplicate-submit protection. A moderation queue is required for production.

## 4. Markdown contract
MD-001 Dialect version `stmts-md/1`: CommonMark 0.31.2 baseline plus GFM-style tables, strikethrough and read-only task lists. Allow paragraphs, h1–h6, strong/emphasis, unordered/ordered lists, blockquotes, thematic breaks, fenced code with optional language, inline code, explicit links and attached images. No raw HTML, embedded CSS, scripts, iframes, SVG from users, executable diagrams, math, footnotes or arbitrary embeds in MVP. Unsupported syntax remains readable literal text. The selected parser MUST be configured to this subset and locked in the application repository.
MD-002 Title is a separate field (0–160 Unicode code points), summary optional (0–280); body is required unless at least one ready attachment exists. Body max 50,000 Unicode code points, max 2,000 parsed blocks and nesting depth 12. Whitespace-only content does not count. Source is authoritative; sanitized structured content is derived. Parser limits MUST fail with useful line-based feedback, never silently truncate.
MD-003 Renderer maps source body headings to display heading levels 2–6 under the document title to maintain one accessible page h1. If title absent, use a visually hidden “Statement by {author}” page h1 and still map body headings to 2–6. Source heading depth is retained separately. Native maps headings to equivalent accessibility traits. TOC needs ≥3 headings and deterministic unique anchor IDs derived from block IDs, not unstable title text.
MD-004 Links permit https/http and mailto; protocol-relative URLs, javascript/data/file schemes are rejected. Same-app links navigate internally; external destinations expose destination and use safe opener handling on web. Do not fetch pasted URLs for previews in MVP. Mention/tag linkification occurs only in plain text nodes, never code/URLs. Handles resolve through API and remain text if unresolved.
MD-005 User image URLs MUST NOT be fetched directly. Composer inserts `![alt](stmts-media:UUID)` after upload; renderer resolves owned attachment IDs to authorized CDN resources. Pasted external images remain text with an “Import image” flow requiring explicit action and safe server-side validation. Attached video is a structured attachment rendered below the relevant media block, not arbitrary HTML in source. Unknown attachment IDs show Missing media and block publishing until removed or repaired.
MD-006 All clients MUST pass the same fixture corpus for structure, links, list nesting, code, emoji, RTL, tables, alt text, and malicious payloads. Renderers consume a canonical typed block tree from the server for published posts; native clients do not use an unrestricted web HTML view. Preview may use a local parser but MUST reconcile with server preview before publishing. Server parsing/sanitization, URL validation and authorization remain mandatory even when clients validate.
MD-007 Angular MUST bind only sanitized renderer output through normal framework bindings; MUST NOT use bypassSecurityTrustHtml on user content. Prefer a typed block renderer with escaped text leaves. Restrict attributes and URL schemes server-side and client-side. Apply CSP and test XSS payloads. Never compile user content into Angular templates. Markdown syntax alone is not a security boundary.

## 5. Composer and draft lifecycle
WRITE-001 Composer MUST offer Write and Preview on compact/medium; expanded MAY split at ≥1200px if each pane can fit ≥480px. Title, body, attachment list and selection survive mode changes and rotation. Toolbar inserts source at selection and restores focus; support bold, italic, heading, quote, list, link, code and attachment. Cmd/Ctrl+B and I are editor-scoped; Cmd/Ctrl+Enter opens publish review, never silently posts. Keyboard help is discoverable.
WRITE-002 Debounce local draft snapshot 500ms and remote save 1,000ms after inactivity. Show Unsaved changes → Saving → Saved at {time}; offline says Saved on this device, never Saved remotely. Native encrypted app storage / web IndexedDB holds drafts scoped to the account. Sign-out warns about unsynced drafts; account switch MUST NOT expose another user's drafts. Clear cached content and tokens per privacy policy.
WRITE-003 Remote saves require revision-based conflict detection (If-Match or revision). On conflict, retain both copies, show “This draft changed on another device,” offer review/duplicate/reload; reload requires confirmation if local changes exist. Undo source edits locally; never overwrite a remote newer revision automatically.
WRITE-004 Publish requires authentication, content within limits, remote preview success for latest source revision, ready media, alt text or decorative designation on images, completed audience review. Button remains disabled during sending with explanation/status. Server takes an idempotency key and draft revision. Retry reuses the key until outcome is known. Successful publication transitions to reader and clears the draft only after server confirmation.
WRITE-005 On save/publish failure retain source, title, attachments and cursor. Offline publishing is unavailable; show Retry when online, never queue an automatic public post. Navigation away from unsaved remote changes prompts Keep editing / Keep local draft and leave; destructive Discard requires a second explicit choice. Preserve upload state while switching tabs; background upload support can vary by OS and must be described honestly.

## 6. Media requirements (proposed product limits)
MEDIA-001 A post supports up to 4 images OR 1 video, not both in MVP. Image inputs JPEG/PNG/WebP/HEIC; max 20 MiB each; normalize orientation, strip GPS/EXIF and convert to delivery variants. HEIC requires server decoding; fail accessibly if unavailable. SVG/GIF input unsupported in MVP. Video input MP4/MOV up to 250 MiB and 180s; MIME, magic bytes, dimensions and duration MUST be verified server-side. Output playback variants are a backend decision; provide broadly supported H.264/AAC MP4 fallback. Client validation is advisory.
MEDIA-002 Lifecycle: selected → validating → uploading (progress/cancel) → processing → ready; errors keep file and offer retry/remove. Expired uploads restart safely. Ready means server scanning and variant generation succeeded. Media cannot publish while pending, failed, or quarantined. A durable upload ID makes retry resumable where supported. Cancel cleans up temporary server objects by policy.
MEDIA-003 Image alt text max 1,000 Unicode code points or explicit decorative flag, never filename as fallback. Caption max 500. Cover crop stores normalized x/y focal point; feed cover 16:9, full reader original ratio. Do not permanently crop source. Lightbox supports keyboard arrows/Escape and platform dismissal, focus restoration, pinch zoom, position announcement. No gesture-only action.
MEDIA-004 Videos never autoplay; use explicit play, pause, scrub, elapsed/duration, mute, captions, fullscreen and accessible player labels. Creator provides transcript or captions when speech/audio information is present, or declares no meaningful audio; caption processing status appears before publication. Support WebVTT ingestion and server validation. No speech recognition is promised by this spec. Respect data saver; do not prefetch full video in feed. Failed playback retains poster and Retry. Demo artwork is not a video file.
MEDIA-005 Content warnings prevent image fetch/display beyond an appropriate neutral placeholder until reveal when feasible. Media authorization, malware scanning, abuse moderation, retention and deletion are backend release gates. Server must prevent unauthorized access even through a copied resource URL.

## 7. Search, notifications, profile, settings
AUX-001 Search debounces 300ms, cancels stale requests, stores query in URL and supports Posts/People/Tags filters. Empty query offers recent local searches with clear history. No results preserves query and suggests a different term. Errors preserve prior results and offer retry. Respect blocked/muted entities. MVP search is not a promise of semantic ranking.
AUX-002 Notifications group repeated reactions per post without concealing actor identities. Unread count is capped visually at 99+ with full accessible count; mark read only after opening or explicit Mark all read. Deleted targets show unavailable. Push is opt-in and separate from in-app notifications, with deep-link permission rechecks.
AUX-003 Profile editing validates display name ≤80, bio ≤500, handle 3–30 ASCII letters/digits/underscore, case-insensitive unique; changing handle retains ID and old links redirect when safely reserved. Avatar is optional; default initials are decorative alongside visible name. Follow button exposes pending/error states. Tabs have real routes or query state and keyboard semantics.
AUX-004 Settings MUST offer System/Light/Dark appearance, reduced-motion preference (OS reduction always respected), data saver and sign out. Theme is applied before first paint and stored per account/device. Reading text follows system scaling; optional reading-size preference may supplement it without disabling system scaling. Account deletion and privacy flows require backend policy before release.

## 8. Accessibility and localization
A11Y-001 Web target WCAG 2.2 AA. Native MUST support VoiceOver/TalkBack, Dynamic Type/fontScale, bold text, switch/keyboard navigation, reduced motion and safe areas. Baseline targets: web/iOS 44 units, Android 48dp. Text contrast ≥4.5:1; large text and essential UI boundaries/icons ≥3:1. Decorative separators may be subtler. Form fields use muted-color borders (not decorative line token) so boundaries remain visible.
A11Y-002 All controls have descriptive accessible names and state. Menus/dialogs manage focus, close via Escape/back and restore invoker focus. Announce saves/errors politely; publish success may move focus to the new reader h1. Do not announce every keystroke, reaction count or time update.
A11Y-003 At 320 CSS px and 200% text zoom, no page-level horizontal scroll except contained tables/code. At 400% browser zoom, layout reflows to one column as available width contracts. Native largest accessibility text size collapses rails and wraps labels without clipping. Skeletons are hidden from assistive technology.
A11Y-004 Strings are externalized; relative dates/numbers/plurals localized. Use logical spacing properties and natural RTL layout; code stays LTR inside a labeled scroll area. Test Arabic, long German strings, CJK line breaks, emoji and mixed bidi text. Moderation and text validation must use Unicode-aware libraries, never byte count in UI.

## 9. Data and client boundaries
See contracts.ts for shape examples. IDs are opaque strings; timestamps UTC ISO 8601; client display is localized. Every mutation is server-authorized. Do not expose tokens in post URLs or local diagnostics.
| Operation | Contract and failure behavior |
|---|---|
| GET /v1/feed?mode=following&cursor= | Page<PostSummary>; nextCursor null at end; 401 reauth |
| GET /v1/posts/:id | Current post + typed blocks; 404 neutral unavailable; permission enforced |
| POST /v1/drafts; PATCH /v1/drafts/:id | Draft plus revision; 409 conflict preserves local copy |
| POST /v1/preview | Source/dialect/attachment IDs → canonical blocks + validation errors + source revision hash |
| POST /v1/posts | draftId/revision/previewHash + Idempotency-Key → published post; 422 field errors |
| PUT /v1/posts/:id/like, /bookmark, /repost | {active:boolean}; server returns canonical count/state |
| POST /v1/uploads | Validated metadata → upload session; complete/status/cancel endpoints required |
| PUT /v1/users/:id/follow, /mute, /block | {active:boolean}; auth and relationship policy enforced |
| POST /v1/reports | target/reason/details; deduplicated submission |

API-001 Errors use `{code,message,fieldErrors?,requestId,retryAfter?}` with safe user copy; distinguish offline/401/403/404/409/413/422/429/5xx. Rate limits show retry guidance and retain inputs. Automatic retry is limited to safe/idempotent operations; publication idempotency is server-enforced. HTTP cache rules MUST exclude private drafts from shared caches.
API-002 Python implementation SHOULD generate a versioned OpenAPI contract used by all clients. Store Markdown source, dialect version and revision; derive canonical blocks, excerpt, plain text and media manifest. Block nodes include stable ID, discriminated type, safe text/children, allowed link URL or attachment ID; never arbitrary style or HTML. Server is authoritative for permissions and content eligibility.
API-003 Client loading/empty/error/offline/success states MUST be explicit view models. Cache public reads with last-updated timestamp and policy; private/account-scoped caches clear on sign-out. Deleted content cannot remain indefinitely available in persistent caches.

## 10. Layout and performance gates
UI-001 Numeric values in tokens/design-tokens.json own visual baseline. Native dimensions map to logical pt/dp, fonts to scalable text styles; never use unscaled absolute pixel text. No fixed body heights. Expanded shell max 1280 with nav216/feed≤680/rail272/gaps24; actual available width may reduce feed before hiding rail at <1200. Compact gutters16; other gutters24.
UI-002 Controls MUST expose focus/pressed/selected/loading/error state, reserve layout during fetch, and provide text alternative to gestures. Follow buttons and upload progress cannot unexpectedly move focus. All menus must work without hover.
PERF-001 Proposed launch budgets: LCP ≤2.5s, INP ≤200ms, CLS ≤0.1 at 75th percentile for web public pages. Treat these as measured goals, not claims about the kit. Responsive images reserve aspect ratio, load thumbnails lazily after the first viewport, and never ship full-resolution originals in the feed. Native lists use stable IDs and lazy rendering; test sustained scrolling on a representative midrange Android device.
PERF-002 Angular public reader/profile SHOULD support SSR for share metadata and indexing, excluding drafts. Sanitize SEO snippets, derive Open Graph images from authorized media only, and honor removed content. Native apps open universal/app links to the same canonical resource. Do not inject unsanitized Markdown into metadata.

## 11. Release acceptance
REL-001 Required screens: signed-out reader/sign-in, Following/Discover, reader/replies, compose/preview/media/drafts, profile/edit, saved, notifications, search, settings, report/block flows. Screen studies cover the central visual surfaces; engineering extends the same components to remaining routes using this spec.
REL-002 Run acceptance scenarios, shared Markdown fixtures and API contract tests on all three clients. Validate compact 320/390, medium 834, expanded 1440 CSS widths; iPhone/iPad split view; Android phone/tablet; both themes; largest text; RTL; keyboard/screen readers; offline/save conflict; interrupted upload; stale/duplicated publish response.
REL-003 No production release until authorization, moderation/report operations, media validation/scanning, privacy/deletion/retention policies, accessibility audit and actual device verification are complete. Do not describe this asset kit as passing application-level tests.
